# 任务感知路由需求

状态：需求、设计已确认；用户明确授权按顺序完成后续任务与实现验证，无需再次询问。

## 目标与范围

跨用户回合维护当前任务下一步工作的能力需求。复杂工作中的“继续”不因消息短而被误降档；明确续接可有限复用，减少重复 Jev 调用；独立新任务不继承旧任务的难度。

第一版采用“任务连续性＋有限复用＋滚动最大值降档保护”，不默认使用指数加权平均。调整颗粒度为**用户回合级**：执行过程中收集重评信号，下一用户路由时评估；同一执行回合的工具跟进、重试保持实际物理派发。

术语见 [CONTEXT.md](../../../CONTEXT.md)，可复用方案及来源见 [调研记录](../../../docs/task-aware-routing-research.md)。这里估计的是下一阶段最低足够能力，不是永久标记整个任务很难。

## 立项时的行为与前置条件

- 立项时 `src/index.ts` 每个新用户回合评估一次，按稳定 turnId 去重，工具跟进和重试保持实际派发。
- 立项时 `src/judge.ts` 提供近期用户/助手文本，但缺少明确任务上下文，每条历史最多 256 字符。
- `src/gears.ts` 保留三个模型档位与五个能力区间，偏置为 `gearBias × 0.4`。
- Pi virtual-model JSON 状态跟随 session 分支，支持恢复和压缩；分类接口支持一次调用多个问题。
- 保留物理模型可用性检查、thinking 裁剪、取消、禁用、direct 和兜底，不新建运行服务或数据库。

## R1：任务连续性

1. 用户回合与任务拥有不同身份；新消息不一定是新任务。
2. 保存有界任务原始需求、近期实质性需求变更和最新有效判决。
3. 可信地确认独立新任务时清空旧任务难度历史，直接评估新任务，不等待降档窗口。
4. 同任务阶段变化可以改变所需能力；第一版通过有效判决窗口确认降低，不设置阶段标签直接降档旁路。
5. 任务关系不明、上下文不足或任务可能已经结束时必须重评，不无条件继承。
6. “继续”本身不证明完成，也不证明下一阶段简单。

## R2：可靠续接与免评估

1. 只有有效任务状态、明确纯文本续接、未到复用上限且没有待重评原因时才免评估。
2. 第一版使用保守完整匹配白名单，不按消息长度或关键词子串短路。
3. “继续，另外增加权限校验”、带非文本附件的续接、确认/感谢/结束表达不因短而自动继承。
4. 继承保持原实际模型和 thinking，不制造分数、不衰减难度、不增加置信度或窗口样本。
5. 同轮重复路由、工具跟进和重试不增加用户复用计数。
6. 分类失败、目标降级、禁用、缺任务身份、关系不明或配置不一致不得建立后续免评估资格。
7. 原物理模型不可用时放弃跨轮免评估，执行正常评估和可用目标选择。

## R3：事件与周期重评

1. 连续继承有可配置有限上限，零关闭跨轮免评估；同轮去重仍保留。
2. 实质性新要求、意图不明、续接过期、低置信度、上下文缺失、配置变化或支持的执行变化，触发下一用户回合重评。
3. 失败验证只触发评估，不直接证明要更强模型；网络失败、provider 重试、任意工具错误不直接增加分数。
4. 缺失/不完整工具元数据不推断成功、完成或降档条件成立。
5. 降档待确认提前触发复核；同上下文没有新增证据时不制造确认，也不因此陷入无限每轮调用分类器的循环。
6. 周期重评是兜底，不声称无分类器就能检测全部语义变化。
7. 第一版不在长执行回合内部即时升级，不实现 provider 自动故障转移。

## R4：有界分类上下文

1. 有当前任务时，一次 Jev 调用同时评估任务关系和下一步所需最低能力；不额外调用一个任务识别模型。
2. 优先发送当前请求、任务锚点、近期实质性变更和公开执行/方案信息。
3. “继续”的评分对应其隐含工作，不对应字面语言难度。
4. 历史分数由本地保护逻辑使用，默认不发给 Jev，避免数字锚定；旧任务文本只是背景，不覆盖新的独立请求。
5. 所有输入有明确预算；排除 thinking、配置/凭据文件读取、图片载荷、原始工具输出和工具参数。
6. 工具新增信息仅为有界结构性事实；文本截断不等于通用秘密脱敏，不承诺过滤用户自己提供的所有敏感文字。
7. 标签、分数、置信度、stopReason 分别验证；部分答案不能当成可信续接或降档许可。

## R5：快速升级与窗口降档

1. 降档保护只使用真实、可信、同任务且可区分观测上下文的判决；继承、重试、重复上下文不增加支持样本。
2. 新判决需要更高能力区间时立即升级，不被历史低分或窗口填充延迟。
3. 同任务降低能力使用最近有效样本窗口的最大分数和降档裕量；窗口不足不降低。
4. 一个新高分打断低需求支持；低置信度、关系不明、分类失败和配置变化打断窗口连续性。
5. 被拒绝的降档仍保留真实观测；窗口最高需求、承诺能力区间和实际派发分别保存。
6. 关系不明只对本轮取旧承诺需求与本次有效需求的较高者，要求重评，不把不确定新分数并入已确认历史。后续可信新任务可以解除临时高档。
7. 原始分数、偏置后分数、降档保护分数、承诺区间及实际派发可区分；gearBias 只应用一次。
8. 模型能力裁剪或目标不可用降级不能改写任务能力需求。
9. 近期不同观测不等于独立统计实验，窗口不提供未经校准的正确率保证。

## R6：生命周期与兼容

1. 状态可 JSON 序列化、跟随分支，在 reload、resume、fork、压缩和 tree 导航中恢复对应历史，不混用分支。
2. 旧状态可继续用于同轮物理派发，下一新用户回合新建有效任务状态后才能跨轮继承。
3. Jev 失败沿用现有同轮兜底；下一用户回合再次尝试，不无限继承失败状态。
4. 取消不提交新的判决、兜底、窗口或复用计数；已经实际发生的执行事实不伪装成未发生。
5. 保留 `enabled:false`、direct、认证检查和手选物理模型的原生 `/thinking` 行为；`gears/auto` 不接受手工 thinking 覆盖。
6. 路由配置改变使下一新用户回合重新评估，但不改变已冻结的同轮派发。
7. 不修改个人 Pi 设置、凭据、远端服务或记忆扩展。

## R7：可观测性

1. footer 区分新判决、继承、周期重评、降档保护、关系不明和 fallback。
2. 继承显示原分数与复用次数，明确本轮没有调用 Jev；失败不冒充有新评分。
3. 仍通过 `ctx.ui.setStatus()` 追加状态，仅在 TUI 运行，不替换原生 footer。
4. 保存决策来源、触发原因、任务与回合身份、分数来源、实际派发和未知信息。
5. 无有效判决的 token 字段为零不代表失败请求没有费用；不保证减少分类调用就必然减少总费用。

| ID | 场景 | 预期 |
|---|---|---|
| A1 | 复杂任务 1.92 后发“继续” | 原实际模型/thinking，无新 Jev、无新样本。 |
| A2 | 三轮合法继承后再续接 | 默认上限 3 时，第四轮结合任务上下文重评。 |
| A3 | “继续，另外增加权限校验” | 立即评估变更范围，不命中关键词短路。 |
| A4 | 困难任务后独立改 README 标题 | 新 taskId、清空历史、不强留 heavy。 |
| A5 | 同任务 0.70 后出现 1.92 | 立即请求 heavy/xhigh，物理能力裁剪另计。 |
| A6 | 1.8 附近小幅波动 | 不因未确认的轻微低分降低 xhigh。 |
| A7 | 1.92 后不同有效进展分别为 1.70、1.68 | 第一个低样本保持，窗口确认后可降 heavy/high。 |
| A8 | 助手仅声称“完成了”后再续接 | 可以重评，不凭自述确认成功或立即降档。 |
| A9 | 执行中支持的验证失败 | 下一用户回合重评，同轮派发不变。 |
| A10 | Jev 失败后“继续” | 同轮兜底，下一用户回合尝试 Jev。 |
| A11 | 重复路由、重试或很多工具调用 | 不增加复用次数，不重复用户判决。 |
| A12 | 恢复、fork、压缩、tree 导航 | 对应分支状态，不泄漏其他分支任务。 |
| A13 | 旧状态或配置改变 | 下一新用户回合重评，同轮保持。 |
| A14 | 续接文本附图片 | 不盲目继承，按支持输入评估或兜底。 |
| A15 | 评估期间取消 | 不提交新判决/窗口/计数。 |
| A16 | 同上下文重复得两个低分 | 不视为两次新任务进展，不推进降档。 |
| A17 | 降档复核无新上下文 | 保持高档，不无限强制每轮重评；仍遵守有限复用。 |

## 待校准的初始参数

- 连续免评估上限 `maxInheritedTurns=3`。
- 降档有效样本窗口 `downgradeWindow=2`。
- 降档裕量 `downgradeMargin=0.08`。
- 可信准入门槛 `minConfidence=0.8`。

这些是初值，不是实测最优配置；不再同时加入 `α=0.7` 和独立连续确认计数。设计阶段明确校验范围、预算、去重范围及迁移规则。

- `types.ts`、`gears.ts`、`settings.ts` 增加可选版本状态与校验；没有新运行依赖。

- 联网脚本先转发 `pi.on`，再验证独立请求与跨轮继承的不同调用次数。
- 实现验证后再更新 README 的运行承诺；旧联网记录不证明新策略有效。
