# 两阶段路由与一次切换

> 历史决策：Skill 推荐、计划修订与仅一次切换的条款已由 [ADR 0002](0002-single-mode-routing.md) 取代。当前实现以单一模式规格为准。

默认任务路由改为计划与实现两个路由阶段。会话从高能力模型的计划阶段开始，只有用户的明确确认才切换一次到较低思考深度的实现模型；之后发现重大偏差时进入计划修订，仍使用实现模型。

这是为了避免按每条消息分数换模型或思考深度。Pi 与 Claude Code 都说明这种切换会重建 prompt cache。两阶段把这笔成本限制为每条连续会话一次。按用户确认的权限边界，plan 只做阶段提示，所有工具权限完全交给 Pi 及已有权限扩展；本扩展不补建只读沙箱、不限制 shell 语法，也不拦截工具发现或 MCP 调用。task 的计划修订和 legacy 的 planning/recovery 同样遵守这一边界，阶段确认与 handoff 仅控制路由，不授予操作权限。

## 考虑过的方案

- 会话锁定单一模型：缓存最稳，但计划和实现使用同一能力与思考深度。
- 按消息分数随时换档：能力匹配更细，但会反复重建缓存。
- 复用旧六阶段 workflow：控制更多，但超出本次只需要计划、实现和一次修订的范围。

## 后果

计划阶段只推荐一个需求、探索或规划 Skill；实现阶段只推荐一个执行或验证 Skill。推荐不等于已读取或已批准。阶段确认提供继续、留下和自由补充；取消、空输入和未明确确认的补充都不切换。TUI 选择框只响应明确开始实现或修订请求，不因当前处于计划阶段而在每条用户消息前出现；计划状态本身不是计划已完成的证据。只有用户明确要求时，才从实现模型切回计划模型。
