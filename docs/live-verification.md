# Jev 与模型服务联网验证记录

验证日期：2026-10-09（UTC）。

## 环境与范围

- 使用项目当前扩展，通过 Pi SDK 创建临时内存会话。
- 使用个人 Pi 配置中的 `typesafe/jev-latest` 和 Magpie 网关，不打印凭据。
- `gearBias = 0`，分类超时 15 秒；light 使用 low，standard / heavy 使用 high。
- 仅使用合成任务与临时文件，不读取业务仓库；只启用 read 工具。
- 每个模型请求最多 6,000 输出 tokens，单轮最多 100 秒，禁用自动重试和缓存预热。
- 凭据复制到临时目录，测试结束后删除；个人配置未改动。

## 首次尝试与修正

首次测试脚本在扩展注册虚拟模型之前选取 `gears/auto`，导致 Pi 使用默认物理模型。请求得到答案，但 Jev 调用次数为零，测试断言失败。

修正测试初始化顺序：先创建并绑定扩展，再显式选择注册后的 `gears/auto`，同时断言当前选择正确。没有为此修改产品路由代码。

## 同一会话的四轮测试

| 任务 | Jev 分数 | 派发档位 / 模型 | 分类耗时 | 整轮耗时 |
|---|---:|---|---:|---:|
| 简单算术 `2 + 2` | 0 | light / space-bunny-free | 2.268 秒 | 4.840 秒 |
| 支付并发、幂等与崩溃窗口分析 | 1.99 | heavy / GPT-6.1 Sol | 0.990 秒 | 16.941 秒 |
| 读取临时文件并返回标记 | 0 | light / space-bunny-free | 1.098 秒 | 4.142 秒 |
| 新的独立算术 `3 + 4` | 0 | light / space-bunny-free | 0.559 秒 | 2.308 秒 |

检查结果：

- 四轮分别调用一次真实 Jev，共四次；四个 turnId 均不同。
- 每轮保存有效判决，`fallback = false`。
- 派发按新任务变化：light → heavy → light → light。
- 算术答案分别为 `4` 和 `7`。
- 文件读取执行一次 read，随后出现 continuation；工具前后均使用 space-bunny-free / low，continuation 不再调用 Jev。
- 所有最终模型响应为正常结束且非空。
- 未自然命中的 standard 模型单独执行连接探测：GPT-6 Luna 返回 `PONG`，耗时 1.200 秒。

## 扩展测试

另一次五轮会话加入了一个 TypeScript 名称清洗函数任务。Jev 给出 `0.06`，选择 light，并正常返回实现。这不是 standard 档故障：简单、明确、低风险任务按最低足够能力原则进入 light，符合当前判题标准。五轮各调用一次分类器，工具跟进仍未额外分类。

随后单独测试常规 React + TypeScript 功能实现，包含搜索防抖、URL 状态与浏览器前进后退、分页、加载/错误状态及过期请求处理：

| Jev 分数 | 置信度 | 派发模型 | 分类耗时 | 整轮耗时 |
|---:|---:|---|---:|---:|
| 0.76 | 0.64 | standard / GPT-6 Luna / high | 0.998 秒 | 15.723 秒 |

该请求正常结束，模型响应非空，判决未兜底。至此，三个档位均通过真实分类派发或连接探测，standard 也自然命中过。

## 结论与边界

本次验证确认：真实 Jev 可用、三个配置模型服务可用、新用户任务会重新判断、档位可以升降、工具跟进固定物理模型且不重复分类。

这不是模型能力基准或输出质量保证：没有编译、运行模型生成的 React 组件。该回答还提示其局部变量需要改为 `useRef`，因此不能直接作为合格实现使用。

未通过真实故障注入验证 provider 重试、分类超时、所有目标不可用或上下文溢出；这些路由分支仍以本地自动测试为依据。小样本结果不能保证后续任务命中同样分数。

服务上报的 cost 字段为零，不代表所有调用免费；本项目无法确认实际账单金额。

## 重跑

```sh
node test/live-smoke.mjs --run
node test/live-smoke.mjs --run --standard-only
```
